## Sparsity

Sparse input is the operating regime, not a compromise: the twin transform *requires*
it. On a complete graph over tabula's 5007 vertices A_E would carry ~10^11 nonzeros and
A_tne would span 12.5 M nodes, so a dense-input comparison is not an experiment that
could be run at any budget. Where the edge set was therefore a *choice*, the choice is
declared here and checked against the graph rather than trusted.

## Weight-source consistency

| dataset | shared pairs | same edge set | global ρ | per-row ρ | unmixed per-row ρ |
|---|---|---|---|---|---|
| `tabula` | 49368 | yes | -0.2364 | -0.782 | -1 |

`unmixed per-row ρ` restricts to the pairs the raw stored matrix recorded in one
direction only, where a symmetrisation cannot have mixed one row's parameters into
another's. It is what separates *the two sources disagree* from *symmetrisation
blurred an otherwise exact relationship*, and on tabula it settles the question:
exactly −1 wherever it can be seen unmixed.

Not comparable, because a side is an indicator or a single constant weight and so carries no ranks — nothing could disagree: `ring_of_cliques`, `tree_of_cliques`, `small_world`, `barabasi_albert`, `karate`, `football_2023`, `sbm_er_3modes`.

## Why each dataset is in the roster

**`ring_of_cliques`** — 10 cliques of 4 vertices joined in a ring. The cleanest case where the twin transform should separate dense groups from the sparse links between them.

**`tree_of_cliques`** — A depth-3 tree of 4-cliques with 3 children each. Hierarchical, and the case the crossing metrics are most visible on.

**`small_world`** — Watts-Strogatz ring, n=150, k=12, rewiring p=0.01. Locally dense with a known ground-truth geometry — the ring — so a layout can be judged by eye.

**`barabasi_albert`** — Preferential attachment, n=1000, k=7. Heavy-tailed degree, which is the regime where the twin transform's cost is worst and hub crowding is most visible.

**`karate`** — Zachary's karate club as stored in karate.mat: unweighted, and the smallest combinatorial case in the roster. The club split is not in the file — see karate_weighted for the labelled variant.

**`karate_weighted`** — nx.karate_club_graph, carrying Zachary's 1-7 interaction strengths. The small count-weighted case, and the only one that exercises the strength -> 1/w derivation.

**`football_2023`** — NCAA Division I FBS 2023 season; an edge is a game played. The conference / division hierarchy is the worked example for composite-label scoring: TNE claims to reveal the sub-conference sub-clusters, and the composite label is what tests that directly.

**`sbm_er_3modes`** — Stochastic block model with Erdos-Renyi background, three modes. Dense (mean degree 55) relative to the rest of the roster, which makes it the case where the line graph is most expensive.

**`digits`** — sklearn's 8x8 handwritten digits as a symmetric k-NN network. Retained as the representative point-cloud-derived k-NN network, present to test whether the twin transform improves on t-SNE-style point-cloud embeddings. Contrast with tabula, which is the same kind of object built better: both come from a point cloud, but tabula persisted its distance matrix *and* its affinities, while digits persists only distances and must derive the rest.

**`tabula`** — Tabula Sapiens liver: single-cell transcriptomes as a UMAP fuzzy simplicial set over an exact 14-NN graph in a 50-d scVI latent space. The only dataset that stores both sides — measured distances and adaptive affinities from the same source — which is what a point-cloud-derived graph should do.
